# 결제 수단: de-slop 시안 A / B

작성: draft-c, 2026-11-12. 기준: `docs/design/impeccable/critique/payment.md`(19/28), `slop-inventory.md`, `apps/mobile/DESIGN.md`.
비교 대상(현재): `chromium-{light,dark}-43-payment.jpg`.

상태는 현재와 같아요. 이 버전에는 결제 기능이 없어서 화면은 '연결할 수 없다'는 사실과, 연결할 수 있게 되면 카드를 어떻게 지킬지를 말해요. 추가 버튼은 두 시안 모두 없어요. 문구는 critique가 고치라고 한 곳만 바꿨어요.

현재 캡처는 design-director가 HEAD b3c2629에서 다시 찍은 것이에요(95c51d3 Flat Paper, ace3eb7 more 화면 정리 반영, 깽이 색 hue 96 고정). 이 캡처와 HEAD `PaymentScreen.tsx`를 함께 봤어요. HEAD는 ace3eb7에서 약속을 넷에서 셋으로 줄이고 행 판을 뺐어요. 무엇이 남았는지는 아래 'HEAD(b3c2629)에서 이미 고쳐진 것'에 있어요.

**`fixes` 표기.** meta.json과 각 HTML kit-meta의 `fixes`에는 HEAD(b3c2629)에 아직 남아 있는 것만 있어요. HEAD가 이미 다 고친 항목은 `fixes`에서 빼고, 아래 'HEAD(b3c2629)에서 이미 고쳐진 것' 절에 고친 커밋과 함께 적었어요. 일부만 고쳐진 항목과 앱과 다른 방향으로 고친 항목은 `fixes`에 남기고, 무엇이 남았는지나 무엇이 다른지를 같은 절에 적었어요. 본문의 '(HEAD에서 이미 고쳐짐)' 표시도 같은 뜻이에요.

## 두 시안이 함께 고친 것

- **'아직 없어요'가 아니라 '아직 못 해요' (P2-1).** 앱 전체에서 '아직 … 없어요'는 '아직 추가하지 않았어요'라는 뜻이라, 읽는 사람이 추가 버튼부터 찾아요. 그래서 상태를 '연결할 수 없어요'로 말해요. 본문은 '깽이가 대신 결제하는 일도 하지 않아요.' 한 문장만 남겼어요. '이 버전에서는 … 연결할 수 없어요'는 제목과 같은 말이에요.
- **판과 글리프 제거 (IT-18; HEAD에서 이미 고쳐짐).** 원 판은 HEAD `EmptyState.css`에서 이미 빠졌고, 판 없는 30px 카드 글리프만 남아 있어요. slop-inventory가 허용한 모양이라 IT-18은 `fixes`에서 뺐어요. 시안은 글리프도 빼요. 문장이 상태를 말해요.
- **약속은 셋, 순서가 아니니까 `<ul>` (P2-2).** 섹션 이름은 '결제 수단을 연결할 수 있게 되면'이에요. 아직 정하지 않은 기능을 '이렇게 지켜요'라고 단정하지 않아요.
  - 기기 암호화와 보안 금고는 같은 약속이라 한 행으로 합쳤어요.
  - '"보내기 전에 묻기"를 꺼도' 각주는 2행 안으로 들어갔어요. 실제 설정 이름과 맞지 않는 인용은 '정보 공개 범위 설정'으로 바꿨어요.
  - 이름은 '모시도'와 '깽이가'가 섞여 있었어요. 이제 에이전트 이름(깽이) 하나예요.
- **타일과 그림자 제거 (P2-3, IT-16, SH-1; HEAD에서 이미 고쳐짐).** 평평한 종이 위에 행 사이 hairline만 있어요(16px 들여쓰기). HEAD도 그림자와 행 판이 없어요. HEAD는 행 사이를 간격으로만 나눠요.
- **첫 화면에 다 보여요 (P3-1).** critique 캡처에서는 '결제할 때마다 물어봐요' 행이 탭 바에 잘렸어요. 이 화면에서 가장 중요한 약속인데도요. HEAD(b3c2629)는 약속이 셋이라 Chrome에서는 세 행이 다 보이지만, WebKit에서는 본문이 한 줄 더 감겨서 셋째 행 본문이 탭 바에 걸려요. 두 시안 모두 세 행이 탭 바 위에서 끝나요. 빈 상태 본문 폭은 `17em`이라 Chrome과 WebKit에서 같은 줄로 감겨요(이전 `28ch`).
- **큰 제목은 '결제 수단' (critique Minor).** 나의 모시 시안의 행 이름과 같아요. 빈 화면 위에서 '연결된'은 이미 카드가 있다고 짐작하게 해요.
- **진짜 h2 (P2-4; HEAD에서 이미 고쳐짐).** 상태 문장과 섹션 제목이 `h2`예요. HEAD도 `SectionLabel` 기본이 `h2`라 detector `skipped-heading` 1건은 이미 없어졌어요.
- **상단.** 뒤로 원과 탭 바, 유리 모양 둘이에요. 에이전트 이름 캡슐은 없어요(RH-1).

## HEAD(b3c2629)에서 이미 고쳐진 것

현재 캡처(43)는 b3c2629에서 찍었어요. 캡처(Chrome, WebKit)와 코드를 같이 보고 나눴어요.

**고쳐짐 (`fixes`에서 뺐어요)**
- 단계 타일(P2-3, IT-16; ace3eb7)과 종이 그림자(SH-1; 95c51d3)
- 단계의 안심 문구(CP-5; ace3eb7): 암호화 설명이 빠지고 '저장된 로그인처럼 보관해요' 한 행이 됐어요.
- 빈 상태 원 판(IT-18; 95c51d3): 판 없는 30px 글리프만 남았어요.
- 제목 단계(P2-4; 95c51d3)

**일부만 고쳐짐 (`fixes`에 남겼어요)**
- 약속(P2-2; ace3eb7): 넷이 셋이 됐고, 1·2행이 합쳐졌고, '모시도'가 빠졌고, 따로 있던 메모가 2행 안으로 들어갔어요. 남은 것은 `<ol>`, 실제 설정 이름과 다른 '"보내기 전에 묻기"' 인용, 단정하는 섹션 이름 '결제 수단이 생기면 이렇게 지켜요'예요.
- 없는 기능의 단계 목록(GR-R2): 셋이 됐지만 여전히 지금 시제의 약속 목록이에요.
- 첫 화면(P3-1): Chrome에서는 다 보이지만, WebKit에서는 셋째 행 본문이 탭 바에 걸려요. 빈 상태 폭은 아직 `28ch`예요.

**그대로예요 (`fixes`에 남겼어요)**
- '아직 연결된 … 없어요' 제목과 맥락 없는 '저장된 로그인 보기'(P2-1)
- 큰 제목 '연결된 결제 수단'
- critique 질문 3: HEAD는 지금 시제의 약속 셋이에요. B의 답(결제가 나와도 참인 가장 작은 화면)과 달라요.

## A: 정직한 빈 상태 (보수적)

- 가운데 정렬 빈 상태(`EmptyState`)를 그대로 쓰고, 제목, 본문, 행동 하나만 고쳤어요. 글리프 없는 변형이에요(`icon`을 선택 항목으로).
- 행동은 MOTION-SPEC §8.14의 '진짜 행동 하나'를 지키되, 하는 일대로 이름을 바꿨어요: **'로그인 정보는 어떻게 지키는지 보기'**. 열리는 곳은 지금처럼 저장된 로그인 금고예요.
- 약속 행은 지금처럼 제목과 본문이에요: 기기에서 잠가요 / 결제할 때마다 물어봐요 / 모두 기록에 남아요. 본문이 제목을 되풀이하지 않게 2행 본문 끝을 '정보 공개 범위 설정과 관계없어요.'로 줄였어요.
- 아쉬운 점: 큰 제목 '결제 수단' 바로 아래에서 '결제 수단은 …'을 다시 말해요(critique가 준 제목 문구 그대로라서).

## B: 첫 문장이 상태 (대담하게)

- **빈 상태 블록이 없어요.** 큰 제목 바로 아래 왼쪽 정렬로 '아직 연결할 수 없어요'(title3)와 '깽이가 대신 결제하는 일도 하지 않아요.'가 와요. 제목이 이미 '결제 수단'이라 문장에서 되풀이하지 않아요. 가운데 정렬 블록과 왼쪽 정렬 목록이 섞이던 정렬도 하나로 맞춰져요.
- **약속은 문장 행이에요.** critique가 준 세 문장을 그대로 썼어요. 행 제목이 없어서 제목과 본문이 같은 말을 두 번 하지 않아요.
- **링크는 이유가 있는 자리로 (P2-1 첫 번째 안).** 1행을 '카드 정보는 저장된 로그인처럼 이 기기에서 암호화돼요…'로 쓰고, 그 바로 아래 글자 링크 '저장된 로그인 보기'(`--accent-text`, 44px 터치 높이)를 뒀어요. 왜 금고로 가는지 문장이 말해 줘요.
- **결제가 나와도 참인 가장 작은 화면 (critique 질문 3).** 결제가 생기면 상태 문장 자리에 카드 행 하나가 들어오고, 나머지는 그대로 참이에요.

## A와 B 비교, 추천

| | A | B |
| --- | --- | --- |
| 상태 | 가운데 빈 상태(제목 + 한 문장 + 버튼) | 큰 제목 아래 왼쪽 정렬 두 줄 |
| '결제 수단' 반복 | 큰 제목과 빈 상태 제목에서 두 번 | 한 번 |
| 금고로 가는 길 | 빈 상태의 유일한 버튼(이름을 고침) | 저장된 로그인을 말하는 행 아래 링크 |
| 약속 행 | 제목 + 본문 | 문장 하나 |
| 바뀌는 범위 | `EmptyState` 변형, 문구 | 화면 구성, 문구 |

**추천: B.** critique가 짚은 세 가지가 B에서 모양으로 같이 풀려요. 상태를 '추가 안 함'으로 읽는 문제, 맥락 없는 금고 버튼, 같은 말 반복이에요. 화면에 있는 것도 종이 묶음 하나와 문장 둘뿐이라 이 화면이 할 일(정직하게 말하기)에 맞아요. `EmptyState`를 그대로 쓰고 싶으면 A도 바로 낼 수 있어요.

## 유지하는 모션 (MOTION-SPEC)

- §6.6: 나의 모시의 '결제 수단' 행 제목이 이 화면의 큰 제목으로 morph하고, `camera` 슬라이드가 따라와요.
- §3 press: 버튼과 링크는 누르는 프레임에 평평한 `--press-tint`가 보여요. 금고는 push로 열려요.
- §8.2: 금고에서 돌아오면 이 화면은 첫 프레임부터 그대로 보여요. 재등장이나 페이드는 없어요.
- 이 화면에는 상태 변화가 없어서 다른 모션 행은 해당하지 않아요.

## 검사

- **impeccable detector** (엔진 0.1.18 캐시 바이너리, `detect --cdp`, Chrome light 390×844): A 0건, B 0건이에요. AI-tell, `skipped-heading`, `low-contrast`, `text-occlusion` 모두 없어요. 현재 앱은 `skipped-heading` 1이었고, `organic-clip-path` 1은 유리 오탐이었어요.
- 대비: 본문 `--label`, 보조 `--label-2`, 링크 `--accent-text`(light #0071E3 4.6:1, dark #5AACFF 종이 위 7.1:1, 95c51d3 값)예요.

## 열린 질문 (critique)

- 결제가 정해지기 전까지 이 행이 나의 모시에 있어야 할지는 제품 판단이에요(질문 1). 없앤다면 정보 공개 범위 footer의 "결제와 지우기처럼 되돌릴 수 없는 일은 … 항상 확인받아요"(settings 시안)가 그 약속을 이미 해요.
- '결제가 필요한 일이 생기면 깽이가 어떻게 하는지'(질문 2)는 지금 앱이 실제로 어떻게 하는지 확인되지 않아서 시안에 쓰지 않았어요.
