## A: 번호는 그대로, 말은 따로 (보수안)

- 카드 구조는 지금과 같아요(제목 → 내용 → 세로로 쌓인 두 버튼). 내용만 세 줄로 나눴어요: 번호 / 대본 / 한 방향 안내.
- 대본은 따옴표가 바깥으로 걸리는 들여쓰기(hanging punctuation)라, WebKit에서 여는 따옴표가 줄 끝에 홀로 남는 문제가
  생기지 않아요(비평 Engine differences).
- "길게 누르거나, 두 번 눌러 확인해요"를 버튼 아래 보이는 글자로(design-director 권장). 지금 앱에 있는 제스처(ConfirmButton
  holdMs 1200, 같은 자리 두 번 탭)를 알려 줄 뿐이라 보수안 범위예요. `aria-describedby`는 그대로.

## B: 번호가 주인공, 대본은 깽이의 목소리 (과감안)

- 위계를 "승인하는 사람이 확인할 순서"로: 제목 → **번호 22px**(대조할 단 하나의 사실) → 구분선 → 깽이 아바타 점 +
  대본(상대가 듣는 건 깽이 목소리) → 한 방향 안내 → "전화 걸기".
- "길게 누르거나, 두 번 눌러 확인해요"를 버튼 아래 **보이는 글자**로(비평 Sam: 지금은 화면 낭독기에만 있음).
- 깽이의 말은 말풍선 없이 바탕 위 글자(채팅 B와 같은 규칙), 턴 머리는 아바타 점 + "1단계 · 1초".

**추천: B.** 이 카드의 일은 "이 번호로 이 말을 해도 되는지" 확인받는 것이라, 번호를 가장 크게 두는 편이 실수를 막아요.
대본 앞 깽이 아바타는 상대가 듣는 목소리가 누구인지 알려 줘요. 기능 문제(P1-1, P1-2)는 HEAD에서 이미 고쳐져서, 두 안의
차이는 번호의 크기와 대본 앞 아바타예요. 보이는 확인 안내 한 줄은 두 안 모두 있어요.

비평 Questions Q1(질문형 전화를 "다시 연락 주세요"로 바꾸기)은 대본 템플릿, 즉 제품 결정이라 두 안 모두 대본은 픽스처
그대로 두었어요. 정해지면 대본 끝만 "…가능한지, 이 번호로 다시 연락 주실 수 있을까요?"로 바뀌고 카드 모양은 같아요.
