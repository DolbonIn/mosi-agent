# services/stt — 로컬 한국어 받아쓰기 (Whisper large-v3-turbo, MLX)

모시가 Google Meet 회의 소리를 받아 적을 때 쓰는 로컬 STT 서버예요. services/meet 봇이 VAD로 자른 발화를 보내면
글자로 돌려줍니다. 127.0.0.1에만 열려 있고, 모델은 계속 메모리에 올려 둡니다(약 2 GB).

## 설치와 실행

```sh
services/stt/setup.sh     # 처음 한 번: .venv 만들고 mlx-whisper 0.4.3 설치, 모델을 HF 캐시에 받음
services/stt/start.sh     # 127.0.0.1:8782 (STT_PORT로 바꿈), 오프라인(HF_HUB_OFFLINE=1)으로 실행
```

- 켜자마자 모델을 올리고 한 번 돌려서 데워 둡니다(약 2~4초). 그동안 `/stt`는 503 `loading`을 돌려줘요.
- services/tts(Drama-3)와 같은 GPU를 쓰지만 프로세스가 달라서 같이 띄워도 됩니다.
- 한 번에 하나씩 받아 적습니다. 동시에 들어온 요청은 프로세스 안의 잠금 하나에 줄을 섭니다.
- `mlx-audio`의 whisper 로더는 이 모델 스냅숏에서 "Processor not found"로 실패하니 쓰지 마세요.

## 계약 (docs/architecture/MEET-CONTRACT.md §1)

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/health` | `{ok, ready, model, queue}`. `queue`는 처리 중이거나 기다리는 요청 수 |
| POST | `/stt?lang=ko&prompt=…` | 본문: raw s16le 16 kHz mono (`Content-Type: audio/L16; rate=16000`), 최대 30초(960,000바이트). 응답: `200 {text, ms, durationMs, noSpeech}`. `prompt`는 아래 "이름 알아듣기" 참고 |

오류는 이렇게 돌려줍니다.
- 400 `empty_body`: 빈 본문
- 400 `too_long`: 30초 초과
- 400 `bad_rate`: Content-Type에 16000이 아닌 rate가 적힘
- 503 `loading`: 모델을 올리는 중
- 500 `transcription_failed`

`ms`는 이 요청을 처리한 시간(잠금 대기 포함), `durationMs`는 받은 오디오 길이예요.

## 무음·잡음 거르기

Whisper는 조용하거나 잡음뿐인 구간에서 "감사합니다.", "시청해 주셔서 감사합니다" 같은 문장을 지어냅니다.
그런 경우에는 `{text: "", noSpeech: true}`를 돌려줘요. 거르는 순서는 아래와 같습니다.

1. **음량**: RMS가 −50 dBFS보다 작으면 모델을 돌리지 않습니다(`STT_SILENCE_DBFS`).
2. **유성음 검사**: 40 ms 프레임마다 60~400 Hz 주기성(자기상관)을 봅니다. 유성 프레임이 5% 미만이거나 합쳐서 120 ms 미만이면
   말소리가 아니라고 봅니다(`STT_MIN_VOICED_RATIO`, `STT_MIN_VOICED_MS`). 음높이가 한 번도 안 바뀌는 소리(삐 소리, 험)도 걸러요.
   - 이 검사가 필요한 까닭: whisper-large-v3-turbo는 순수 잡음에도 `no_speech_prob`를 0.000으로 내고 "감사합니다."라고 답합니다.
   - 측정한 유성 프레임 비율
     - 걸러야 할 소리: 흰색·분홍·갈색 잡음 0.00, 440 Hz 삐 소리와 120 Hz 험 0.00
     - 말소리: 깨끗한 말 0.64~0.69, 잡음 섞인 말 0.68, Opus 16 kbps를 거친 말 0.69, 말 뒤에 무음 3초 0.21
3. **세그먼트 기준**: `no_speech_prob > 0.6`이면서 `avg_logprob < −1.0`이면 버립니다. 압축률이 2.4를 넘어도(같은 말 되풀이) 버려요.
4. **알려진 환각 문구**: 문장 전체가 유튜브식 인사·자막 크레디트("시청해 주셔서 감사합니다", "구독과 좋아요", "자막 제공 …",
   "MBC 뉴스 ○○○입니다" 등)이거나 그것을 되풀이한 것이면 버립니다. 그런 낱말이 들어 있을 뿐인 보통 문장("알림 설정은 내일 바꿀게요")은 남겨요.

## 이름 알아듣기 (initial prompt)

맥락 없이 짧게 "모시야"라고 부르면 Whisper가 "5시야", "모시자", "무시아"로 적어요(2026-11-12 실제 회의 시험).
그래서 이름이 든 문장을 initial prompt로 넣어 그쪽으로 기울게 합니다.

- 기본 문장: "모시야, 지금 회의 내용 좀 정리해 줄래?"(`STT_PROMPT`로 바꾸고, `STT_PROMPT=""`이면 끔)
- 요청마다 `?prompt=…`로 바꿀 수 있어요(최대 200자). 회의 봇은 서버가 준 문장(사용자 에이전트 이름)을 붙여요.
  빈 `?prompt=`는 그 요청만 끕니다.
- 프롬프트 문장은 로그에 남기지 않아요.
- **프롬프트 메아리 거르기**: 짧고 흐린 소리에서 Whisper가 프롬프트를 그대로 돌려줄 때가 있어요. 그대로 두면 누가
  모시를 부른 것처럼 보이니까 버립니다. 버리는 조건은 두 가지가 다 맞을 때예요.
  - 결과가 프롬프트와 같거나 프롬프트의 긴 조각(8글자 이상)이다.
  - 오디오 길이에 비해 글자가 너무 많다(초당 9음절 초과).
  - 그래서 사람이 정말 그 문장을 말하면(2~3초) 그대로 받아 적어요. 서버(apps/server meet.ts)도 같은 규칙으로 한 번 더 걸러요.
  - 실제 모델에서 메아리가 얼마나 자주 나오는지는 아직 재지 않았어요.

## 측정 (M3 Max, 2026-11-11)

| 입력 | 처리 시간 |
|---|---|
| 한국어 3.2초 | 254~261 ms |
| 한국어 7.1초 (두 문장) | 286~297 ms |
| 잡음·무음 (모델 안 돌림) | 0~1 ms |
| 3개 동시 요청 | 0.26 / 0.49 / 0.92 초 (줄 서서 처리) |
| 시작부터 준비 완료까지 | 2.2~3.9초 |

- Drama-3가 문장을 만드는 동안에도 한국어 3.2초짜리가 290~304 ms로 거의 그대로였어요.
- 이 Mac에서 처음 실행했을 때는 데우기 뒤 첫 요청이 14초 걸렸습니다(처음 한 번 Metal 커널을 컴파일한 것으로 보여요).
  그 뒤 다시 켰을 때는 첫 요청도 0.26초였습니다.

## 로그

길이와 시간만 남깁니다. 예: `3157 ms audio -> 20 chars in 261 ms`. 받아 적은 문장은 로그에 남기지 않아요.
